>
> 用法：每层分「概念必答」「动手验证」「面试高频」。勾选标准不是「看过」，而是：
>
> - 概念必答：不查资料能用自己的话讲清，并能回答「它解决谁的什么问题、没有它会怎样、代价是什么」

## 0. 全局主线：先背这张因果链

`模型太大 → 单卡装不下 → 3D 并行 → 千卡协作需高速互联 → 卡多了故障成日常 → Checkpoint 容错 → 训完要服务几亿人 → 推理优化 → 体验与成本走钢丝 → TTFT / 吞吐 / MFU → 模型要持续变好 → 数据管道 + MLOps 闭环`

- [ ] 能在 2 分钟内把这条链讲完，并且每一步都能说出「它解决了上一步留下的什么代价」
- [ ] 能把六层画在一张白纸上，并给每层配一个类比（视频用的是「连锁餐厅后厨」）
- [ ] 能说清 AI Infra 与算法/机器学习的分界：Infra 管「怎么跑」，不管「跑什么」

## L1 硬件层（灶台与火力）

**概念必答**

- [ ] CPU vs GPU：CPU 是「几个教授做微积分」，GPU 是「几千个小学生做加法」；神经网络 90%+ 计算是矩阵乘法，需要人海而非智商
- [ ] FLOPs / PFLOPS / Tensor Core：为什么把矩阵乘做成一条硬件指令等于开绿色通道
- [ ] HBM 与**内存墙**：算力增长快于数据搬运，为什么带宽常比容量更关键
- [ ] 量级感：H100 80GB HBM3 / >3TB/s，B200 192GB HBM3E / 8TB/s，B300 288GB
- [ ] CUDA 生态护城河：为什么 AMD、昇腾、寒武纪、TPU/NPU 纸面算力不差却难替代（硬件可追、生态难速成）
- [ ] 互联分层：机内 NVLink（H100 900GB/s → B200 NVLink5 1.8TB/s）、跨机 InfiniBand/高性能以太网 + RDMA
- [ ] 功率与机房：8 卡 H100 满载 >10kW，液冷、数据中心向水电/风电旁选址

**动手验证**

- [ ] 用 `nvidia-smi` / DCGM 采集显存、利用率、温度、功耗，能区分「算力空转」与「显存打满」
- [ ] 跑一次小矩阵乘或模型前向，观察 GPU 利用率随 batch 增大的变化曲线

**面试高频**

- [ ] 「为什么大模型推理往往是带宽瓶颈而不是算力瓶颈？」——伏笔在这层，答案在 L4 decode 阶段
- [ ] 采购 GPU 时除了 FLOPs 还要看什么：显存容量/带宽、互联、软件生态、功耗、TCO

## L2 集群与网络（后厨传菜通道）

**概念必答**

- [ ] 能画出「单机 8 卡 → 多机组网」拓扑，说清哪一层通信走 NVLink、哪一层走 InfiniBand
- [ ] NCCL / AllReduce 与 RDMA 的关系；为什么 RDMA 能绕过 CPU 直接读写远端内存
- [ ] 通信量级决定排兵布阵：话多的放同一间办公室，话少的跨楼协作

**动手验证**

- [ ] 有环境时跑 `nvidia-smi topo -m` 看拓扑；能读懂 NCCL 日志里的 `algbw` / `busbw`

**面试高频**

- [ ] 「为什么 3D 并行必须按通信量级摆放？」——答案要把 L2 和 L3 连起来讲

## L3 训练平台（中央厨房研发部）

**概念必答**

- [ ] **显存账**：70B 模型 FP16 仅权重 140GB > 单卡 80GB；梯度 + AdamW 状态约 16 字节/参数 ≈ 1.1TB；加激活值轻松破 2TB —— 分布式不是炫技，是活不下去
- [ ] 数据并行 DP：每卡一份完整模型、数据切片、AllReduce 对答案；前提是单卡装得下
- [ ] ZeRO / FSDP：把优化器状态、梯度、参数本身也切片，用时临时凑齐
- [ ] 张量并行 TP：拆矩阵本身，每层都要通信 → 只能在机内 NVLink 卡间用
- [ ] 流水线并行 PP：按层切段，micro batch 消「气泡 bubble」
- [ ] 3D 并行的实际组合：机内 TP + 机间 PP + 外层 DP 横向复制
- [ ] 混合精度：FP16/BF16 前向反向 + FP32 主权重累积，为什么几乎白拿两倍速度
- [ ] Checkpoint 容错：Meta 公开 Llama 3 训练 54 天中断 400+ 次（约每 3 小时一次）；存档间隔是真金白银（万卡 2 小时 ≈ 2 万卡时）
- [ ] 存档工程：异步存、分片存、并行文件系统承接热存档、对象存储归档冷存档
- [ ] 慢卡（straggler）比宕机更可怕：一张慢卡拖住几千张卡；监控采集温度、ECC 报错、通信延迟
- [ ] Slurm / Kubernetes 多租户：配额、排队公平、优先级抢占、碎片整理

**动手验证**

- [ ] 用 DeepSpeed 或 FSDP 跑一次 tiny 模型（2 卡或单卡模拟），对比开启前后的显存占用
- [ ] 手动 kill 训练进程，从最近 checkpoint 恢复一次，记录丢失的步数与耗时

**面试高频**

- [ ] 三种并行各自的通信开销、适用场景，以及「TP 为什么不能跨机」
- [ ] 「万卡集群为什么故障是日常」，如何设计自动检测 → 隔离坏卡 → 从存档拉起的闭环

## L4 推理服务（门店现炒出餐）★ 转型第一落点

**概念必答**

- [ ] 训练是炼丹（一锤子买卖），推理是开饭馆（天天营业、又便宜又稳）；钱的大头在推理
- [ ] token 与自回归：每生成一个 token 都要重读前文 → 所有优化都冲着「别做重复工、别让 GPU 闲着」
- [ ] KV Cache：缓存不变的 Key/Value；长上下文 + 高并发下比模型权重还吃显存
- [ ] PagedAttention / vLLM：借操作系统分页管理 KV Cache，把碎片浪费压到接近 0
- [ ] Continuous Batching vs static batching：以 token 粒度「谁吃完谁走」，吞吐翻几倍，现已是标配
- [ ] 量化：FP16 → INT8/INT4、FP8/FP4，显存砍半再砍半；数据变小搬运也快，代价是精度需评估
- [ ] 蒸馏：大模型当老师写解题过程，小模型照着学（DeepSeek R1 蒸馏系列是代表）
- [ ] **Prefill / Decode 两阶段**：prefill 算力密集可大规模并行，decode 逐 token、带宽密集、算力单元空转
- [ ] **PD 分离**：两组卡各干各的，中间传 KV Cache，按负载独立扩容；大规模集群标配
- [ ] Prefix cache 命中可省掉整个 prefill；智能路由按负载 + 前缀亲和分发
- [ ] 引擎版图：vLLM（开源顶流）、TensorRT-LLM、SGLang
- [ ] 算子融合 / FlashAttention（中间结果不落显存）；投机解码（小模型打草稿、大模型批量验收）
- [ ] MoE 与专家并行：每 token 只激活部分专家省算力，但所有专家得在显存待命，推高显存与多卡通信要求

**动手验证（对齐 90 天 vLLM + K8s 计划）**

- [ ] 用 vLLM 起一个开源小模型，跑通 OpenAI 兼容 API
- [ ] 压测：不同并发 / batch 下记录 TTFT、TPOT、吞吐（tokens/s）、KV Cache 显存占用
- [ ] 开关 `--enable-prefix-caching`，量化多轮对话场景下的 TTFT 差异
- [ ] 试一次 INT4/AWQ 量化，对比显存、吞吐与输出质量
- [ ] 把上述指标接进 Prometheus + Grafana（**不要只采 GPU utilization**）

**面试高频**

- [ ] 带宽瓶颈完整推导：decode 阶段反复搬权重与 KV Cache，计算单元喂不饱 → 同卡跑 decode 时功率上不去
- [ ] PagedAttention 和 Continuous Batching 分别消除了哪种浪费
- [ ] PD 分离解决了什么、引入了什么新成本（KV Cache 跨卡传输、调度复杂度）
- [ ] 「同样一张 GPU，为什么跑 decode 功率反而上不去」（视频留给评论区的题）

## L5 服务与成本（前厅点单收银）

**概念必答**

- [ ] 延迟 ↔ 吞吐跷跷板：batch 越大单位 token 成本越低但用户等越久，平衡点就是服务层的日常工作
- [ ] TTFT（首 token 延迟，由 prefill 决定）与 TPOT（每 token 间隔，由 decode 决定）
- [ ] 弹性伸缩的难点在**冷启动**：几十上百 GB 模型加载要几分钟 → 模型预热、镜像加速、显存快照
- [ ] SLA/SLO 与降级策略：付费用户优先、长文请求排队、必要时切量化小模型顶
- [ ] token 经济学：卡时租金 ÷ 每小时产出 token 数 = 每 token 成本
- [ ] **为什么输入 token 比输出 token 便宜几倍**：输入走 prefill 一次并行算完，输出走 decode 逐个蹦、带宽受限、占机时间长
- [ ] MFU（算力真正干活的比例）：不少团队长期 <30%，30% → 60% 等于白得一倍算力
- [ ] 自建 / 租弹性 GPU / 按 token 付费托管 API 的成本拐点：量大且稳定自建划算，波动大租更灵活

**动手验证**

- [ ] 给自己的 vLLM 服务写一条 SLO（如 P99 TTFT < 2s）和一条可执行的降级规则
- [ ] Grafana 看板至少含：TTFT、TPOT、吞吐、prefix cache 命中率、KV Cache 占用、GPU 利用率 / MFU 估算

**面试高频**

- [ ] 「输入 token 为什么比输出 token 便宜」
- [ ] 「高峰期既要保 P99 TTFT 又要控成本，你怎么取舍」

## L6 数据与 MLOps（供应链与质检）★ DevOps 平移最省力

**概念必答**

- [ ] 模型的上限是数据定的，算力只负责兑现上限；「垃圾进垃圾出」在大模型时代被放大
- [ ] 数据管道：采集 → 去重 → 过滤低质 → 清洗有害 → 主题/语言配比 → 合成数据 → 版本化 → 合规（版权、隐私、敏感信息）
- [ ] embedding / 向量库：「我想吃火锅」与「附近有什么川菜」字面不同但坐标相邻
- [ ] RAG：检索增强生成 = 让模型开卷考试，不重训就能答企业内部文档，是企业落地 AI 最主流方式
- [ ] MLOps 五环闭环：实验跟踪（W&B、MLflow）→ 模型注册（版本 + 审批）→ 评估流水线（基准 + 安全）→ 灰度发布 / A-B → 线上监控（效果漂移、延迟、错误率、翻车案例）→ 回流数据管道
- [ ] 为什么「闭环转得快」才是壁垒：模型不是训练一次的艺术品，是持续迭代的工业品

**动手验证**

- [ ] 用 MLflow（或最小 yaml 记录）跟踪一次微调的超参、数据版本、结果曲线
- [ ] 搭一个最小 RAG：切片 → embedding → 向量库 → 检索 → 生成
- [ ] 把 K8s 滚动更新 / 灰度经验映射到模型上线流程，写一份对照表

**面试高频**

- [ ] 「你做 DevOps 的经验，哪几块能直接平移到 AI Infra」：
      K8s 调度 → 训练/推理编排；Prometheus → GPU 与模型可观测；CI/CD → 评估流水线与灰度；SRE → SLO 与容错；后端高并发 → 推理服务层
- [ ] MLOps 为什么是转行门槛最低、需求量大的入口

## 面试复盘：三个必考题（视频里明确埋的点）

1. **为什么推理常是带宽瓶颈而非算力瓶颈** → L1 内存墙 + L4 decode 搬运
2. **三种并行各自的通信开销与适用场景** → L3 3D 并行 + L2 互联
3. **为什么输入 token 比输出 token 便宜** → L4 prefill/decode 差异 + L5 成本模型

## 学习路线（三步，配 90 天节奏）

- [ ] 第 1 步：云 GPU 上完整跑通一次开源模型微调 + 部署，建立端到端手感（一两百块的事）
- [ ] 第 2 步：从推理入手（离业务最近、上手最快），读一遍 vLLM 文档、自己部署压测，盯 TTFT / 吞吐 / 显存
- [ ] 第 3 步：选一个方向钻 —— 往下 CUDA 与算子优化，往上分布式训练框架，横向 MLOps 平台
- [ ] 加权建议：**L4 + L5 + L6 是 DevOps 背景 ROI 最高的落点**；L1/L2/L3 先掌握概念与排查术语，有千卡环境再深钻
- [ ] 当前阶段明确不投入：PD 分离、专家并行（千卡规模才划算）；手写 CUDA kernel（等 B 路线稳定、开始每周 8 小时研读推理引擎源码时再切入）
- [ ] 记住这行的壁垒不是聪明，是踩过的坑 —— 坑踩得越早越值钱
